# Feast Mode Protocol

One WebSocket per browser tab, at path `/ws` on the same host and port that serves the
client. The client connects with `wss://` when the page is HTTPS (the tunnel) and `ws://`
otherwise: `` `${location.protocol === 'https:' ? 'wss' : 'ws'}://${location.host}/ws` ``.

Every message in both directions is JSON:

```json
{ "type": "TYPE_NAME", "payload": { } }
```

`payload` is always an object (empty `{}` when there is nothing to send). Unknown types,
malformed JSON, missing fields, and wrong field types get an `ERROR` and change nothing.

Ids: player ids are opaque strings generated by the server. Timestamps are Unix epoch
milliseconds.

## Phases

`phase` values, in order:

| Phase             | Game    | Deadline | Ends when                                                              |
|-------------------|---------|----------|------------------------------------------------------------------------|
| `lobby`           | none    | none     | host sends `START_MATCH`                                               |
| `mystery_discuss` | mystery | 100 s    | deadline or host `NEXT`                                                |
| `mystery_vote`    | mystery | 45 s     | all connected round players voted, deadline, or host `NEXT`            |
| `mystery_guess`   | mystery | 30 s     | impostor guessed, impostor disconnected, deadline, or host `NEXT`      |
| `mystery_reveal`  | mystery | none     | host `NEXT`                                                            |
| `wyr_choose`      | wyr     | 30 s     | all connected players submitted, deadline, or host `NEXT`              |
| `wyr_reveal`      | wyr     | none     | host `NEXT`                                                            |
| `paused`          | either  | none     | 3+ players connected again (resumes), or host `END_MATCH`              |
| `match_over`      | none    | none     | host `NEXT` returns everyone to `lobby` with scores reset              |

If the impostor disconnects before `mystery_guess`, the round is void and skips straight
to `mystery_reveal`.

## Client → server

| Type            | Payload                    | Valid when                                                                                                   |
|-----------------|----------------------------|--------------------------------------------------------------------------------------------------------------|
| `CREATE_ROOM`   | `name`                     | Sender is not in a room. Name valid (rules.md).                                                              |
| `JOIN_ROOM`     | `code`, `name`             | Sender not in a room. Room exists, is in `lobby`, has < 10 players, name not taken.                          |
| `REJOIN`        | `code`, `token`            | Sender not in a room. Token matches a player in that room. Any phase.                                        |
| `START_MATCH`   | `{}`                       | `lobby`, host only, 4+ connected players (3+ in test mode).                                                  |
| `CAST_VOTE`     | `targetId` (string or `null`) | `mystery_vote`, sender is in the round, has not voted. `null` means Skip. A string must be a player in the round who is not the sender. |
| `GUESS_WORD`    | `word`                     | `mystery_guess`, sender is the impostor, has not guessed. Word is 1–30 characters after trimming.            |
| `SUBMIT_CHOICE` | `choice`, `prediction` (each `"A"` or `"B"`) | `wyr_choose`, has not submitted.                                                         |
| `NEXT`          | `{}`                       | Host only. Any phase except `lobby` and `paused`.                                                            |
| `END_MATCH`     | `{}`                       | Host only. Any phase except `lobby` and `match_over`. Goes to `match_over`.                                  |

`CAST_VOTE` with the `targetId` key missing is an `ERROR`; only an explicit `null` is Skip.

## Server → client

**Bold** "Sent to" cells carry secrets. They go to one player only. Nothing sent to the
whole room may contain a word or the impostor's identity before the reveal (except a
caught impostor in `VOTE_RESULT`), and no one's vote or Would You Rather choice before
its result message.

| Type | Payload | Sent to |
|---|---|---|
| `JOINED`        | `playerId`, `token`, `code` | **The joining player only.** Reply to `CREATE_ROOM`, `JOIN_ROOM`, `REJOIN`. Client stores `code` and `token` in `localStorage`. |
| `ROOM_STATE`    | `code`, `hostId`, `phase`, `testMode`, `players`: [`{id, name, score, connected}`] | Everyone in the room, on any change to players, host, phase, or scores. |
| `ERROR`         | `reason` (human-readable string) | The sender only. |
| `MATCH_STARTED` | `games`: `["mystery", "wyr"]`, `rounds`: `{mystery: 3, wyr: 3}` | Everyone. |
| `PHASE`         | `game`, `phase`, `round` (1-based), `deadline` (ms timestamp, or `null`) | Everyone. |
| `YOUR_WORD`     | `word`, `isImpostor` | **That player only.** At round start, and again on `REJOIN` during a running round. |
| `SUBMITTED`     | `playerIds`: ids who have acted in the current phase | Everyone, after each accepted vote/guess/choice. Ids only, never content. |
| `VOTE_RESULT`   | `votes`: [`{voterId, targetId}`] (`targetId` `null` = Skip), `accusedId` (`null` if nobody caught), `caught` (bool) | Everyone, at the end of `mystery_vote`. Reveals the impostor only when `caught` is true. |
| `ROUND_RESULT`  | `impostorId`, `mainWord`, `impostorWord`, `guess` (string or `null`), `guessCorrect` (bool or `null`), `void` (bool), `points`: [`{playerId, delta}`] | Everyone, entering `mystery_reveal`. |
| `WYR_PROMPT`    | `optionA`, `optionB` | Everyone, at the start of `wyr_choose`. |
| `WYR_RESULT`    | `choices`: [`{playerId, choice, prediction}`], `countA`, `countB`, `majority` (`"A"`, `"B"`, or `null` on an even split), `points`: [`{playerId, delta}`] | Everyone, entering `wyr_reveal`. |
| `MATCH_OVER`    | `winnerIds` (list; ties are co-champions), `leaderboard`: [`{playerId, name, score}`] sorted high to low | Everyone. |

Scores live in `ROOM_STATE.players[].score`; there is no separate `SCORES` message.

## Rejoin

1. On `JOINED`, the client saves `{code, token}` to `localStorage`.
2. On page load, or when the socket closes, the client reconnects and sends `REJOIN` if it
   has a saved token. On `ERROR`, it clears the token and shows the join screen.
3. The server answers `REJOIN` with `JOINED`, `ROOM_STATE`, the current `PHASE`, and any
   messages the player needs to rebuild the current screen (`YOUR_WORD`, `VOTE_RESULT`,
   `WYR_PROMPT`, results), still respecting the secrecy rules above.
4. If the player has an open socket already, the old socket is closed and replaced.

This matters most on phones: iOS Safari and Chrome on Android drop WebSockets when the
screen locks or the browser goes to the background.

## Error reasons (examples, not exhaustive)

`"not in a room"`, `"room not found"`, `"room is full"`, `"name taken"`,
`"match already started"`, `"not the host"`, `"not enough players"`, `"wrong phase"`,
`"already submitted"`, `"cannot vote for yourself"`, `"not the impostor"`,
`"invalid message"`.
